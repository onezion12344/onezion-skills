# 闲鱼浏览器操作 SOP

## 前置条件

- 用户已在浏览器中登录闲鱼网页版
- 浏览器自动化工具可用（onezion-agent-browser-core）
- 闲鱼网页版地址：https://www.goofish.com

---

## SOP-1：检查消息列表

### 目标
获取所有未读会话列表。

### 步骤
```
1. 打开 https://www.goofish.com/im
2. 等待页面加载完成（等待消息列表元素出现）
3. Snapshot 整个页面
4. 提取所有会话条目：
   - 买家昵称
   - 最后一条消息预览
   - 商品缩略图/标题
   - 是否有未读标记（红点）
5. 返回未读会话列表
```

### 注意
- 如果页面跳转到登录页，说明会话过期，需要用户重新登录
- 如果消息页加载慢，等待 3-5 秒后重试 snapshot
- 每次只处理前 10 个未读会话，避免一次处理太多

---

## SOP-2：读取单个会话

### 目标
读取某个会话的最近消息上下文。

### 步骤
```
1. 从消息列表点击目标会话
2. 等待聊天内容加载（2-3 秒）
3. Snapshot 聊天窗口
4. 提取：
   - 商品信息（标题、价格）
   - 最近 6 条消息（区分买家/卖家）
   - 当前输入框状态（是否可输入）
5. 返回结构化消息数据
```

### 提取格式
```json
{
  "session_id": "xxx",
  "product": {
    "title": "AirPods Pro 2代",
    "price": "899",
    "image": "xxx"
  },
  "buyer": {
    "nickname": "小明",
    "avatar": "xxx"
  },
  "messages": [
    {"role": "buyer", "text": "这个还在吗？", "time": "10:30"},
    {"role": "seller", "text": "在的", "time": "10:31"},
    {"role": "buyer", "text": "能便宜点吗", "time": "10:32"}
  ],
  "unread": true
}
```

## SOP-3：发送回复

### 目标
在会话中发送一条消息。

### 步骤
```
1. 确认当前会话正确（核对买家昵称+商品标题）
2. 定位输入框元素
3. 输入回复文本
4. 截图确认内容正确
5. 等待用户确认发送指令
6. 点击发送按钮
7. 等待发送成功确认（消息出现在聊天记录中）
8. 截图记录发送结果
```

### 注意
- **绝对不自动发送**，必须等待用户确认
- 发送前再次核对会话身份
- 如果输入框被禁用或消失，说明会话异常，停止操作

---

## SOP-4：发布商品

### 目标
在闲鱼发布新商品。

### 步骤
```
1. 打开 https://www.goofish.com/publish
2. 等待发布页面加载
3. 逐步填写：
   a. 上传商品图片（从本地路径选择）
   b. 填写标题
   c. 填写描述正文
   d. 填写价格
   e. 选择分类
   f. 选择标签
   g. 设置交易方式（发货/自提）
4. 每步截图确认
5. 最终预览截图给用户
6. 用户确认后 → 点击发布按钮
```

### 注意
- 图片上传可能需要通过文件选择对话框操作
- 分类选择可能是下拉菜单或弹窗
- 发布按钮点击后等待页面跳转确认发布成功

## SOP-5：批量处理会话

### 目标
高效处理多个未读会话。

### 步骤
```
1. 执行 SOP-1 获取未读列表
2. 按优先级排序：
   - 有"我想要"/"购买"动作的 → 优先
   - 纯咨询 → 次优先
   - 闲聊 → 最后
3. 逐个执行 SOP-2 读取会话
4. 对每个会话生成回复草稿
5. 汇总所有回复建议给用户
6. 用户逐一确认/修改
7. 逐个执行 SOP-3 发送
8. 每批处理 5-10 个，处理完一批后暂停
```

## SOP-6：订单履约比价（买家下单后找货源）

### 目标
买家下单后，在闲鱼搜索同款更便宜的商品作为货源。

**⚠️ 绝对不自动下单、不自动付款。只搜索和比价。**

### 步骤
```
1. 从买家订单中提取商品关键词
2. 打开 https://www.goofish.com/search?q=关键词
3. 等待搜索结果加载
4. Snapshot 搜索结果页
5. 逐个提取商品信息：
   - 标题
   - 价格
   - 卖家信用（极好 > 优秀 > 良好）
   - "XXX人想要"数量
   - 发布时间（越新越好）
6. 筛选：价格 < 买家支付价，信用极好优先
7. 按价格升序排列，取 Top 5
8. 输出比价表格
```

### 搜索关键词提取规则

| 商品类型 | 搜索关键词示例 |
|---------|---------------|
| API Key / Token | "MiMo API" "MiMo Key" "API key" |
| 数字商品 | "会员" "充值" "激活码" |
| 实物商品 | 品牌+型号+规格关键词 |

### 卖家信用等级解读

| 信用等级 | 信任度 | 说明 |
|---------|--------|------|
| **极好** | ⭐⭐⭐ | 首选，交易量大、好评率高 |
| **优秀** | ⭐⭐ | 次选，可以接受 |
| **良好** | ⭐ | 谨慎，检查近期评价 |
| 无标记 | ❌ | 不推荐，可能是新号或问题号 |

### 输出格式

```
📦 订单需求：[商品关键词] | 买家付：¥XX

🔍 Top 5 货源：

| # | 标题 | 价格 | 信用 | 想要 | 利润 |
|---|------|------|------|------|------|
| 1 | xxx | ¥XX | 极好 | 5人 | +¥XX |
| 2 | xxx | ¥XX | 极好 | 2人 | +¥XX |
| 3 | xxx | ¥XX | 优秀 | 8人 | +¥XX |
| 4 | xxx | ¥XX | 优秀 | 1人 | +¥XX |
| 5 | xxx | ¥XX | 良好 | 3人 | +¥XX |

💡 推荐：第 X 个（信用极好 + 最低价 + 利润 ¥XX）
⚠️ 请手动打开链接下单，我不帮你操作支付
```

### 注意
- 同一买家多次下单同一类型商品，缓存上次搜索结果，避免重复搜索
- 数字商品（API Key 等）价格波动快，必须重新搜索，不使用缓存
- 搜索结果可能包含大量无关商品，需要 AI 判断相关性
- 如果搜索结果少于 3 个可靠候选（信用极好），扩大筛选范围到信用优秀

## 错误处理

| 错误 | 处理方式 |
|------|---------|
| 页面跳转到登录 | 停止，提示用户重新登录 |
| 元素找不到 | 等待 2 秒后重试，最多 3 次 |
| 网络超时 | 提示网络问题，稍后重试 |
| 闲鱼反爬检测 | 停止所有操作，提示用户 |
| 发送失败 | 记录失败，告知用户手动发送 |

---

## 风控规避建议

- 每次操作间隔 2-5 秒
- 每批处理不超过 10 个会话
- 不要短时间内频繁刷新页面
- 操作速度模拟人工（不要太快）
- 深夜（00:00-06:00）避免大量操作
